# CTRSE Application — Build Spec (Claude Code-ready)

**Target:** a bespoke, local-first web app that showcases **both** halves of CTRSE — the supervised triage model and the Gen-AI explanation layer — in one designed UI.
**Stack:** FastAPI (thin Python backend + static host, one process) + vanilla HTML/CSS + Alpine.js frontend. No build step. Local-first; remote deploy is a separate follow-up, out of scope here.
**Rubric rows this targets:** Application/Functionality → A; Supervised Model/Deployment → B (local); Source Codes/Structure → reinforces A.

---

## 0. The core invariant (read first — it governs every file)

> **`ctrse_core.py` is the single source of truth for every clinical fact and safety decision.**
> That means: the predicted level (via the exact `argmax → P1-threshold → red-flag-floor` chain), the P1–P4 probability distribution, all 14 payload fields, the confidence word, the level colour/label, the guardrail verdict, and the mandatory disclaimer. **`api.py` serialises these; `static/` only renders them.**
>
> **No level, probability, threshold comparison, confidence label, guardrail decision, or base-rate may be computed in `app.js`, `style.css`, or anywhere in the frontend.** If the frontend needs a derived value (a bar width, a colour), the *fact* it derives from is supplied pre-computed by the API; only pure presentation (px width, which CSS var) happens frontend-side.

This is the invariant the whole architecture exists to protect, and it is a viva answer: *"the model owns the numbers, the LLM owns only prose, and the frontend owns only pixels."*

## 1. File tree & file-by-file responsibilities

```
ctrse_app/
  ctrse_core.py        # ALL safety-critical logic (single source of truth)
  api.py               # FastAPI: endpoints + Gemini proxy + serves static/
  prep_sample.py       # one-off: build the stratified demo-sample artefact
  requirements.txt
  sample/              # generated by prep_sample.py — committed, ships with the app
    patients.json      # precomputed deterministic payloads for every demo patient
    pinned.json        # pinned LLM outputs (from NB3's genai_demo_pinned.json)
    meta.json          # thr_p1, model_name, dep_name_present, counts, feature_count
  static/
    index.html         # single page shell
    style.css          # the bespoke design system (§4)
    app.js             # Alpine: fetch + render only
  tests/
    test_parity.py     # asserts app == notebooks (level, payload, guardrails)
    test_api.py        # FastAPI TestClient: endpoint schemas + offline path
```

### `ctrse_core.py` — owns everything clinical; imports nothing from the app
**Imports:** `numpy`, `joblib`, `os`, `json`, `re`, `google-genai` (lazy/guarded), `shap` (guarded). No FastAPI, no Alpine, no rendering.
**Loads at import (or via `init(artefact_dir)`):** `ctrse_p1p4_model.pkl` bundle, `X_*.npy`, `feature_cols.pkl`, `ordinal_encoder.pkl`, `categorical_cols.pkl`. Reads `THR_P1 = bundle["p1_threshold"]`, `RED_FLAGS = bundle["red_flags"]`, `LABELS/NAMES/p1_class_index` from the bundle — **never hardcoded** (§2).
**Exposes:**
| Symbol | Type | Contract |
|---|---|---|
| `LEVEL_META` | dict | `{"P1":{"label":"CRITICAL","colour":"#d62728"}, "P2":{…"#ff7f0e"}, "P3":{…"#2ca02c"}, "P4":{…"#1f77b4"}}` — the *only* place these strings/hexes live |
| `DISCLAIMER` | str | `"This describes the model's prediction of a triage assignment, not a clinical diagnosis."` |
| `predict_level(row)` | `np.ndarray → "P1".."P4"` | exact chain from §2.3; returns the EPC string |
| `explain(row)` | `np.ndarray → dict` | the 14-field payload (§2.4), field names identical to NB3 |
| `confidence_word(payload)` | `dict → str` | deterministic rule from §2.6 |
| `COMMON_RULES`, `SYSTEM_PROMPT_JUSTIFY`, `SYSTEM_PROMPT_HANDOVER` | str | verbatim from NB3 §3 |
| `build_user_prompt(payload, use_case)` | `→ str` | payload serialised as indented JSON |
| `generate(payload, use_case, prefer_live)` | `→ dict` | Gemini call + guardrail check + offline/pinned fallback; returns `{source, text?/synthesis?+caveat?, guardrails, disclaimer}` |
| `guardrail_check(payload, text, use_case)` | `→ dict` | `{"passed":bool, "flags":[str]}`; behaviour identical to NB3 §4 (§2.5) |
| `GEMINI_AVAILABLE` | bool | true iff key present + library importable |

`generate()` is where live-vs-pinned-vs-offline is decided (§3, `POST /api/explain`). The Gemini API key is read from `os.environ["GEMINI_API_KEY"]` **inside this module only** — it never crosses to the frontend.

### `api.py` — transport only; no clinical logic
**Imports:** `fastapi`, `pydantic`, `fastapi.staticfiles.StaticFiles`, `ctrse_core as core`, the `sample/` JSON. **Owns:** route definitions, request/response models (Pydantic mirrors of §3), reading `sample/patients.json` into memory at startup, mounting `static/` at `/`, and calling `core.generate(...)` for the explain endpoint. **Owns no** thresholds, mappings, or facts — it looks them up from `core`/`sample`. Serves the SPA and the API from one `uvicorn api:app` process.

### `prep_sample.py` — one-off artefact builder
**Imports:** `ctrse_core as core`, `numpy`, `json`, `collections`. **Does:** load `X_test`; select the 3 archetypes (`clear_p1`, `borderline`, `thin_payload` — same selection logic as NB3 §5) **plus** N random rows **stratified** across P1–P4 (default N=60/level → ~240 patients); for each, call `core.explain(row)` and `core.predict_level(row)`; write `sample/patients.json` (id, index, payload, level, colour, label, picker summary). Copies NB3's `genai_demo_pinned.json` → `sample/pinned.json`. Writes `sample/meta.json`. **Run once after the encoder gate (§5, Gate 1); re-run whenever NB1/NB2 artefacts change.**

### `static/index.html` / `style.css` / `app.js`
- **index.html:** the shell — header, sidebar mount, two-panel main, footer, Alpine directives. Loads `style.css`, Alpine (CDN), IBM Plex fonts (CDN), `app.js`.
- **style.css:** the entire design system (§4). No inline styles elsewhere.
- **app.js:** Alpine component(s). `fetch`es the endpoints, holds selected-patient + use-case + source state, maps API fields → DOM. **Contains zero clinical computation** — it reads `level_colour`, `confidence_word`, `probabilities`, etc. straight from responses. The only math permitted is `barWidth = prob * 100 + '%'`.

### `tests/`
- **test_parity.py** — the anti-drift guard (§2.7). **test_api.py** — TestClient hits every endpoint, asserts the §3 schemas, and asserts the offline path (`prefer_live=false`, or no key) returns `source ∈ {pinned, offline}` and never 500.

## 2. Parity with the notebooks (must-match — a mismatch is a viva-killer)

Everything here already exists in NB2/NB3. The app must reproduce it **exactly**, not re-derive it. Where possible, extract the code verbatim into `ctrse_core.py` rather than rewriting.

### 2.1 Threshold
`THR_P1` comes from `bundle["p1_threshold"]` at runtime (**≈0.0941 in the current live bundle**, was ≈0.2286 on the original full run — it moves when Jace refreshes artefacts). **Never hardcode it.** `test_parity` asserts the app's `THR_P1 is bundle["p1_threshold"]`.

### 2.2 Label mapping
`P1=3, P2=2, P3=1, P4=0` (higher int = more urgent). Pull `LABELS`, `NAMES`, `p1_class_index` from the bundle, not from a literal. `p1c = list(model.classes_).index(3)`.

### 2.3 Prediction chain — reproduce verbatim (per row)
NB3 computes, over the whole test set:
```python
pred_op = model.classes_[proba.argmax(1)].copy()
pred_op[proba[:, p1c] >= THR_P1] = 3          # P1 threshold override
pred_final = pred_op.copy()
for rf in RED_FLAGS: pred_final[X[:, COL[rf]] == 1] = 3   # red-flag floor
```
The app's `predict_level(row)` is the single-row form and **must equal `pred_final` for that row** — argmax, *then* P1-threshold override, *then* red-flag floor, in that order. The displayed level is `pred_final`, **not** raw argmax.

### 2.4 Payload — identical 14 keys, identical computation
`predicted_level, probabilities, threshold_context, red_flag_triggered, red_flag_complaint, active_chief_complaints, complaint_base_rates, abnormal_vitals, age, arrival_mode, department, utilisation_history, high_importance_features_present, shap_top_contributors`.
Same rules as NB3 §2: `BASE_RATES` computed **train-only**, `n≥300` floor; `NORMAL` vital bands `o2 94–100, sbp 90–180, hr 50–110, rr 10–24, temp 35.5–38.0 (°C)`; `cc_` prefix stripped; `≤8` caps on complaint/feature lists; absent values → `None`/omitted, never defaulted. **`arrival_mode`/`department` decode through the FIXED encoder (§5 Gate 1).**

### 2.5 Guardrails — identical behaviour to NB3 §4
`guardrail_check` must implement the same scans: untraceable-numbers (strip `\bP[1-4]\b`, `rstrip(".")`, accept ÷100 form for percentages), inactive-complaint mentions (cc vocab ≥6 chars, red-flag complaint exempt), diagnostic-language regexes, reassuring-words-on-P1/P2 hard check, disclaimer presence (check full text first, then strip before body scans), and B-structure (both `Synthesis:` and `Caveat:` labels present). Same `DISCLAIMER` string.

### 2.6 Confidence word — deterministic, from NB3 rendering
`"High (red-flag driven)"` if `red_flag_triggered`; else `"Borderline (near P1 threshold)"` if `threshold_context` contains `"just"`; else `High` if max prob ≥0.85, `Moderate` if ≥0.60, else `Borderline (split)`.

### 2.7 Parity test (the anti-drift guard)
`test_parity.py` loads the sample rows and asserts, **against NB3's regenerated `genai_demo_pinned.json`** (post-Gate-1):
1. app `predict_level(row)` == pinned `predicted_level` for every pinned patient;
2. app `explain(row)` == pinned payload (all 14 keys, deep-equal);
3. app `guardrail_check` verdict == pinned guardrail verdict on the pinned `(payload, text)` pairs.
> **Recommended (not required for PR2):** converge NB3 to `import ctrse_core` so the two literally share one implementation — the only permanent guarantee against drift. For PR2, extract verbatim + this test.

## 3. API contract

All responses `application/json`. Errors return `{"error": str}` with a 4xx/5xx status, never a bare 500 on the offline path.

### `GET /api/meta`
→
```json
{ "model_name": "gemini-3.5-flash", "thr_p1": 0.0941, "chosen_recall": 0.85,
  "n_patients": 240, "dep_name_present": false, "gemini_available": true, "feature_count": 553 }
```

### `GET /api/patients`
→
```json
{ "levels": ["P1","P2","P3","P4"],
  "patients": [
    { "id": "clear_p1", "predicted_level": "P1", "level_label": "CRITICAL",
      "level_colour": "#d62728", "archetype": "clear_p1",
      "summary": "74y · ambulance · cardiacarrest red flag", "p1_probability": 0.982 }
  ] }
```
`archetype ∈ {"clear_p1","borderline","thin_payload", null}`. `summary` is a short, human picker line built server-side from payload facts (age · arrival · a salient flag/complaint).

### `GET /api/patients/{id}`  — deterministic model output (no LLM)
→ the full render-ready model payload:
```json
{ "id": "clear_p1", "predicted_level": "P1", "level_label": "CRITICAL",
  "level_colour": "#d62728", "confidence_word": "High (red-flag driven)",
  "probabilities": { "P1":0.982, "P2":0.014, "P3":0.003, "P4":0.001 },
  "threshold_context": "well above the P1 alert threshold",
  "red_flag_triggered": true, "red_flag_complaint": "cardiacarrest",
  "active_chief_complaints": ["cardiacarrest","chestpain"],
  "complaint_base_rates": [{ "complaint":"cardiacarrest","historical_emergency_rate":1.0,"n_historical":326 }],
  "abnormal_vitals": ["o2=88","rr=28"], "age": 74.0,
  "arrival_mode": "Ambulance", "department": null,
  "utilisation_history": { "n_edvisits":3, "n_admissions":1 },
  "high_importance_features_present": ["cc_cardiacarrest","arrivalmode","age"],
  "shap_top_contributors": [{ "feature":"cc_cardiacarrest","contribution":0.83 }] }
```
`404 {"error":"unknown patient id"}` if not found. Read straight from `sample/patients.json` (precomputed) — no live model call needed per request, which keeps the panel instant.

### `POST /api/explain`  — Gen-AI (live → pinned → offline)
Request:
```json
{ "patient_id": "clear_p1", "use_case": "justify", "prefer_live": true }
```
`use_case ∈ {"justify","handover"}`. Response (justify):
```json
{ "patient_id":"clear_p1", "use_case":"justify", "source":"live",
  "text":"Based on the available indicators, the model weighted …",
  "guardrails": { "passed": true, "flags": [] },
  "disclaimer": "This describes the model's prediction of a triage assignment, not a clinical diagnosis." }
```
Response (handover) — same envelope but instead of `text`:
```json
{ "synthesis":"…one sentence…", "caveat":"…one sentence…" }
```
`source ∈ {"live","pinned","offline"}`. Resolution order in `core.generate`: if `prefer_live && GEMINI_AVAILABLE` → live call (temperature-fallback pattern) + guardrail scan; on any failure or `!prefer_live` → look up `sample/pinned.json`; if no pinned record for this patient → `source:"offline"` with a rendered honest placeholder and `guardrails:{"passed":null,"flags":["offline — no live model this session"]}`. **Never raises to a 500.**

## 4. Design system (spelled out — the bespoke look is specced, not left to taste)

**Identity thesis.** This is an *emergency-triage acuity* tool for *clinicians*, and its one job is to make a machine's acuity decision — and its uncertainty — legible and trustworthy in a glance. So the design puts **acuity itself** at the centre and keeps everything else clinically quiet. The four level colours are the *only* saturated hues on the page; they read as **data**, not decoration. Chrome is neutral ink. **Structure encodes truth:** machine-owned facts are set in **mono**, human/LLM prose in **sans** — the typeface itself tells you which parts are deterministic and which were written by the model. That mono/sans split is the signature.

### 4.1 Tokens — paste into `:root` in `style.css`
```css
:root{
  /* Acuity (data-only saturated hues — from NB1 EDA palette) */
  --p1:#d62728; --p2:#ff7f0e; --p3:#2ca02c; --p4:#1f77b4;
  --p1-tint:#fdecec; --p2-tint:#fff2e6; --p3-tint:#eaf6ea; --p4-tint:#e9f1f8;

  /* Neutral ink scale (chrome — quiet, cool) */
  --bg:#f6f7f9; --surface:#ffffff; --surface-2:#eef1f4;
  --border:#e0e4e9; --border-strong:#cdd3db;
  --text:#161b22; --text-muted:#5a6472; --text-faint:#8b94a1;

  /* One restrained accent for interaction — slate, NOT blue (blue is P4 data) */
  --accent:#334155; --accent-hover:#1e293b; --on-accent:#ffffff;

  /* Status */
  --pass:#1a7f4b; --pass-tint:#e7f4ec; --warn:#b7791f; --warn-tint:#fbf3e4;

  /* Type */
  --font-sans:"IBM Plex Sans", system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
  --font-mono:"IBM Plex Mono", ui-monospace, "SF Mono", Menlo, monospace;
  --fs-xs:.75rem; --fs-sm:.875rem; --fs-base:1rem; --fs-lg:1.125rem;
  --fs-xl:1.5rem; --fs-2xl:2rem;
  --lh-body:1.55; --lh-tight:1.25;

  /* Spacing (4px base) */
  --s1:.25rem; --s2:.5rem; --s3:.75rem; --s4:1rem; --s5:1.5rem; --s6:2rem; --s8:3rem;

  /* Radius & shadow (restrained — clinical, not playful) */
  --r-sm:6px; --r:10px; --r-lg:14px; --r-pill:999px;
  --sh-sm:0 1px 2px rgba(16,24,40,.06); --sh:0 4px 14px rgba(16,24,40,.08);
}
```
**Font loading:** one CDN link — IBM Plex Sans (400/500/600/700) + IBM Plex Mono (400/500). System stack fallback so the app still works offline.

**The mono/sans rule (enforce everywhere):** `--font-mono` for *all* machine facts — probabilities, vitals, ages, `n_historical`, feature ids, the payload JSON, SHAP contributions, thresholds. `--font-sans` for UI labels, buttons, and **the LLM prose** (justification, Synthesis, Caveat). Never mix.

### 4.2 Layout
App shell max-width `1280px`, centred, `--s5` page padding.
```
┌───────────────────────────────────────────────────────────────┐
│ HEADER  CTRSE ▸ triage acuity   [scope badge]        model·thr │  sticky, 64px
├──────────────┬────────────────────────────────────────────────┤
│ SIDEBAR 300px│  MAIN  grid: 1fr 1fr, gap --s5                  │
│  ▸ archetypes│  ┌── MODEL PANEL ──────┐ ┌── GEN-AI PANEL ────┐ │
│  ▸ level     │  │  [signature: acuity │ │ [Justify|Handover] │ │
│    filter    │  │   badge + dist bar] │ │ [Generate] source⬤ │ │
│  ▸ patient   │  │  confidence         │ │ guardrails ✓       │ │
│    list      │  │  red-flag banner    │ │ ── prose / SBAR ── │ │
│  ▸ random    │  │  complaints · vitals│ │                    │ │
│              │  │  drivers · arrival  │ │ disclaimer         │ │
│              │  └─────────────────────┘ └────────────────────┘ │
├──────────────┴────────────────────────────────────────────────┤
│ FOOTER  disclaimer · limitations · ▸ architecture (viva expander)│
└───────────────────────────────────────────────────────────────┘
```
Main collapses to a single column below `900px`; sidebar becomes a top collapsible. Quality floor: responsive to mobile, visible keyboard focus rings (`--accent`), `prefers-reduced-motion` respected.

### 4.3 Signature element — the acuity expression (hero of the Model panel)
One unified block that reads the **decision and its uncertainty together**:
- **Level badge:** solid `var(--p{n})` block, `--on-accent` white text, `--font-sans` 700, `--fs-xl`, letter-spacing `.02em`, `--r`, padding `--s2 --s4`. Content: `P1 · CRITICAL`.
- **Distribution bar directly beneath:** a single horizontal segmented bar, full width, height `14px`, `--r-pill`, four segments coloured `--p1..--p4`, each segment width = that class probability. The predicted class segment is full-opacity; the others at `.45` opacity. A thin vertical tick marks the P1 threshold position on the P1 segment. Below it, four tiny mono readouts `P1 .982 · P2 .014 · …` in `--font-mono --fs-xs tabular-nums`.
This is the memorable element: **the badge is the answer, the bar is the doubt**, in one glance. Everything else on the panel stays quiet.

### 4.4 Component styling
- **Confidence:** micro-label (`--fs-xs`, uppercase, `--text-muted`, letter-spacing `.06em`) + value in `--font-sans` `--fs-sm`. Colour cue: red-flag → `--p1`; borderline → `--warn`; high → `--pass`; moderate → `--text`.
- **Red-flag banner:** shown only when `red_flag_triggered`. Full panel width, `--p1-tint` bg, 3px `--p1` left border, `--r-sm`. Inline ⚠ + `--font-sans` 600: `Red-flag override — cardiacarrest floored to P1`.
- **Chips (complaints, drivers):** `--surface-2` bg, `--text-muted`, `--fs-xs`, padding `--s1 --s3`, `--r-pill`. Complaint text in `--font-mono` (it's a machine field). Base-rate chips append a mono stat: `cardiacarrest ·1.00 emerg· n=326`. The red-flag complaint chip gets `--p1-tint` bg + `--p1` text.
- **Abnormal vitals:** row of stat pills `SpO₂ 88` — label sans, number mono; a small `--p1` dot marks out-of-range.
- **Segmented use-case toggle:** two buttons, `--surface-2` track, active button `--surface` + `--sh-sm` + `--accent` text; inactive `--text-muted`.
- **Generate button:** `--accent` fill, `--on-accent`, `--r`, `--font-sans` 600; hover `--accent-hover`; disabled while awaiting.
- **Source badge:** dot + label. Live → `--pass` dot, `Live model`; Pinned → `--accent` dot, `Pinned example`; Offline → `--warn` dot, `Offline — saved output`.
- **Guardrail status:** pass → `--pass-tint` bg, `--pass` text, `Guardrails ✓ passed`; flagged → `--warn-tint`/`--warn`, `⚑ flagged: <list>`.

### 4.5 The two Gen-AI outputs
- **Justification (A):** the LLM prose in `--font-sans`, `--fs-base`, `--lh-body`, max-width `62ch` for readability. Nothing else — no headers, matching NB3's A format.
- **Handover (B) — SBAR-shaped, deterministic frame + two LLM lines.** A vertical stack of labelled sections, each with a `--border` left rule and an uppercase `--fs-xs` `--text-muted` eyebrow:
  - **SITUATION** — level badge + confidence (deterministic)
  - **BACKGROUND** — key drivers as chips: complaints, arrival mode, age, utilisation (deterministic)
  - **ASSESSMENT** — the LLM **Synthesis** line (`--font-sans`)
  - **CAVEAT** — the LLM **Caveat** line (`--font-sans`)
  Only ASSESSMENT and CAVEAT are model-written; the eyebrows and the SITUATION/BACKGROUND content are code-owned. State this in a tiny footnote for the viva.
- **Disclaimer footer:** always present under both, `--fs-xs`, `--text-faint`, top-border `--border`, the `DISCLAIMER` string verbatim.

### 4.6 Microcopy voice (active, clinical, no filler)
Empty state: `No patient selected — choose one from the list to see the model's assessment.` Offline generate: `Showing a saved example — no live model this session.` Errors state what happened and the fix, in the interface's voice, never an apology.

## 5. Build order, with gates marked

Gates are hard stops — do not proceed past one until it's green.

**GATE 1 (blocks everything demo-facing): encoder fix re-run.**
Re-run patched NB1 §5 → regenerate `ordinal_encoder.pkl` + `categorical_cols.pkl` + `X_*.npy` from the corrected fit → re-run NB3 §2 onward → regenerate `genai_demo_pinned.json`. Until this is done, every payload's `arrival_mode`/`department` is corrupt and the app inherits it. *Nothing below is trustworthy without Gate 1.*

**Phase 1 — `ctrse_core.py`.** Extract logic verbatim from NB2/NB3: loaders, `predict_level`, `explain`, prompts, `guardrail_check`, `generate` (with offline/pinned fallback), `LEVEL_META`, `confidence_word`, `DISCLAIMER`.
- *Validate (no live):* module imports; `explain(row)` on a subsample returns exactly the 14 keys; `guardrail_check` passes NB3's synthetic good/bad unit cases; `predict_level` on sample rows.
- **GATE 2 — `test_parity.py` green** (app level/payload/guardrail == regenerated pinned). Depends on Gate 1.

**Phase 2 — `prep_sample.py`.** Build the stratified sample → `sample/patients.json` + `pinned.json` + `meta.json`.
- *Validate (no live):* file exists; patient count matches; per-level stratification counts correct; every payload has 14 keys; **spot-check `arrival_mode` is a real mode, never an insurance value** (proves Gate 1 stuck).

**Phase 3 — `api.py`.** Endpoints + static mount + `core.generate` wiring.
- *Validate (no live):* `test_api.py` via TestClient hits all four endpoints, asserts §3 schemas.
- **GATE 3 — offline-fallback path.** `POST /api/explain` with `prefer_live=false` (or no key) returns `source ∈ {pinned, offline}`, valid envelope, **never 500**.

**Phase 4 — `static/` (frontend).** `index.html` + `style.css` (§4) + `app.js` (fetch/render only).
- *Validate (no live):* static serves; CSS has no selector-cancellation on section padding/margins (watch `.panel`/`.card` specificity — see frontend note below); Alpine state wires without console errors. **Actual look/render is human-verified (§6).**

**Phase 5 — integration.** `uvicorn api:app`, browse, generate live.
- *Human-verified only (§6).*

> **CSS note for Phase 4:** avoid type-selector vs element-selector padding collisions (e.g. `.panel` and `section`), a common source of cancelled margins. Keep section spacing on one class family.
